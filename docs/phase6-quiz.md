# Phase 6 · 문제 풀기

구현 완료. 원래는 AI로 문제를 실시간 생성할 계획이었지만, **미리 써 둔 문제
은행**으로 바꿨습니다. 그 결정과 그로 인해 사라진 것들을 남겨 둡니다.

## 왜 AI 실시간 생성을 접었나

초안(`phase6-ai-quiz.md`, 삭제됨)은 Anthropic API를 호출해 문제를 그때그때
만드는 구조였습니다. 그러려면 다음이 전부 필요했습니다.

- `@astrojs/vercel` 어댑터와 서버 함수 두 개 (API 키를 브라우저에 못 보내므로)
- Anthropic API 키 발급, 크레딧 충전, 과금 관리
- 남용 방지를 위한 하루 생성 횟수 제한
- 생성 실패·지연에 대한 로딩·오류 처리

문제를 콘텐츠로 저장하면 **이 목록이 통째로 사라집니다.** 서버가 없어지고,
채점은 브라우저에서 즉시 끝나며, 막을 남용도 없습니다. 사이트는 지금처럼
100% 정적으로 남습니다.

품질 면에서도 낫습니다. 실시간 생성은 매번 결과가 흔들리지만, 미리 쓴 문제는
오답 보기 하나까지 손으로 다듬을 수 있습니다. 오답 보기는 개념 문서의
**"흔한 오해" 블록**에서 끌어옵니다 — 그래야 틀렸을 때 진짜로 배웁니다.

대신 치르는 비용은 하나, **문제를 사람이 써야 한다**는 것입니다. 개념이
53개이므로 한 번에 다 채우지 않고 늘려 갑니다.

## 콘텐츠 구조

`src/content/quiz/<concept-slug>.json` — 개념당 파일 하나. 문제가 없는 개념은
파일도 없고, 퀴즈 후보에도 오르지 않습니다.

```json
{
  "conceptSlug": "entropy",
  "questions": [
    {
      "level": 2,
      "question": "엔트로피가 상태함수라는 말은 무슨 뜻입니까?",
      "choices": ["...", "...", "...", "..."],
      "answer": 1,
      "explanation": "상태함수는 현재 상태만으로 값이 결정되는 양입니다. ..."
    }
  ]
}
```

- `level`은 개념 문서와 같은 1~5단계. **그 사람이 읽은 단계 이하의 문제만**
  출제됩니다. 3단계까지 읽은 사람에게 5단계 문제를 내면 시험이 아니라
  함정이기 때문입니다.
- 본문과 같은 인라인 문법(`$수식$`, `**강조**`)을 쓸 수 있습니다.
- `explanation`은 정답 설명에서 그치지 않고 **왜 그 오답에 끌리는지**까지
  짚습니다. 틀린 사람이 읽을 글이기 때문입니다.

빌드 타임에 검증합니다 — 파일명과 `conceptSlug` 불일치, 존재하지 않는 개념,
범위를 벗어난 `answer`는 전부 빌드 실패로 잡힙니다.

## 흐름

```
/quiz  →  저장한 개념 중 문제가 있는 것을 고름 (기본: 전체 선택)
       →  [문제 만들기]  총 5문항, 개념을 한 바퀴씩 도는 라운드 로빈으로 배분
       →  답을 고르고 [채점하기]  — 브라우저에서 즉시 채점
       →  전체 점수 + 개념별 정답률 + 가장 낮은 개념 [다시 학습하기]
       →  user_concepts.understanding 갱신
```

`understanding`은 Phase 4에서 만들어 두고 비워 뒀던 열입니다. 이 기능이
그것을 채웁니다. **누적 평균이 아니라 마지막 점수로 덮어씁니다** — 복습하고
다시 풀었을 때 오른 실력이 곧바로 보여야 "약한 개념 → 복습 → 확인"이 한
바퀴로 돌기 때문입니다.

## 서버가 없는데 DB는 어떻게

지금까지와 똑같습니다. 로그인한 사용자의 브라우저가 anon 키로 Supabase에
직접 쓰고, **RLS가 남의 행을 막습니다.** 새 테이블도, 새 마이그레이션도
필요 없습니다 — `user_concepts.understanding` 열과 기존 정책을 그대로 씁니다.

로그인하지 않은 사람도 퀴즈를 풀 수 있고, 결과는 localStorage에만 남습니다.
나중에 로그인하면 기존 동기화 경로를 타고 함께 올라갑니다.

## 파일

| 파일 | 역할 |
|---|---|
| `src/content/quiz/*.json` | 문제 은행 |
| `src/lib/quiz.ts` | 문제 뽑기·채점 (전부 순수 함수) |
| `src/components/Quiz.tsx` | 화면 (선택 → 풀이 → 결과) |
| `src/pages/quiz.astro` | 빌드 타임에 문제 은행을 실어 보냄 |

## 현상도 문제 은행 대상이다

`src/content/quiz/<slug>.json`의 slug는 개념뿐 아니라 **현상**(`src/content/phenomena/`)
slug도 받는다. `content.ts`의 검증이 개념과 현상 양쪽에서 찾은 뒤에 실패하고,
`quiz.astro`가 두 목록을 합쳐 `Quiz`에 넘긴다. 현상은 `field: 'phenomena'`로
고정하고(`FIELD_META.phenomena` 참고), "다시 학습하기" 링크는 `/p/`로 간다.

## 남은 일

- **문제 채우기는 끝났습니다.** 개념 53개 + 현상 7개, 총 60개 문서 × 5문항 =
  300문항. 이제 콘텐츠가 새로 추가될 때마다 문제도 함께 쓰면 됩니다.
- 개념당 문항이 5개뿐이라 두세 번 풀면 같은 문제가 돕니다. 자주 푸는
  개념부터 10개 이상으로 늘리는 것이 좋습니다.
- 소주제 단위(예: "전자기 유도" 안의 "렌츠의 법칙") 분석은 여전히 범위 밖
  입니다. 개념 하나가 곧 페이지 하나인 현재 구조에서는 "다시 학습하기"로
  보낼 페이지가 없기 때문입니다. 콘텐츠 구조를 바꿔야 가능합니다.
