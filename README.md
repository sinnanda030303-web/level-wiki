# 난이도 슬라이더 백과

같은 개념을 다섯 단계 난이도로 읽는 사이트. 슬라이더를 올리면 설명이 **교체되지 않고 자랍니다.**
비유가 빠지고 수식이 들어오는 식으로 블록이 등장·퇴장하기 때문에, 읽는 사람이
자기 이해가 어디서 끊기는지 스스로 보게 되는 것이 목적입니다.

```bash
npm run dev
```

- `npm run dev` — 개발 서버 (http://localhost:4321)
- `npm run build` — 정적 빌드 (`dist/`)
- `npm run validate` — 콘텐츠 무결성 검사

## 구조

```
src/
  content/concepts/*.json   개념 문서 (파일명 = slug)
  lib/types.ts              레벨·블록 정의, 본문 선택 규칙
  lib/content.ts            문서 로딩, slug 해석
  components/
    ConceptReader.tsx       슬라이더 + 블록 여닫이 (유일한 React 아일랜드)
    RichText.tsx            본문 인라인 문법 렌더러
  pages/
    index.astro             전체 목록 + 검색
    c/[slug].astro          개념 페이지
    f/[field].astro         분야 목록
scripts/validate-content.ts
```

본문은 정적 생성되어 검색엔진에 그대로 노출되고, 슬라이더 부분만 클라이언트에서 살아 움직입니다.
JS가 없어도 L1 내용은 정상적으로 읽힙니다.

## 레벨

| 레벨 | 라벨 | 성격 |
|---|---|---|
| 1 | 감만 잡기 | 비유만, 수식 없음 |
| 2 | 교과서 | 정의와 대표 예시 |
| 3 | 전공 입문 | 수식과 성립 조건 |
| 4 | 전공 심화 | 유도 과정과 예외 |
| 5 | 연구자 | 미해결 쟁점 |

학년이 아니라 목적으로 라벨을 붙였습니다. 학년으로 쓰면 사람들이 자존심 때문에
필요보다 높은 레벨에 머물러, 정작 이 사이트가 알려주려는 것을 못 보게 됩니다.

## 블록

문서는 통짜 글이 아니라 블록의 배열입니다. 블록마다 등장 구간이 정해져 있고,
슬라이더를 움직이면 그 구간에 따라 열리고 닫힙니다.

| 블록 | 기본 구간 | 화면 표시 |
|---|---|---|
| `oneline` | 1–5 | 제목 없이 강조 박스 |
| `analogy` | 1–3 | 비유 |
| `core` | 1–5 | 핵심 |
| `math` | 3–5 | 수식 |
| `misconception` | 2–5 | 흔한 오해 |
| `application` | 2–5 | 어디에 쓰이나 |
| `frontier` | 5 | 아직 안 풀린 문제 |

문서에서 `minLevel` / `maxLevel`로 구간을 덮어쓸 수 있습니다.

## 문서 작성

```json
{
  "slug": "entropy",
  "title": "엔트로피",
  "field": "thermodynamics",
  "summary": "목록 카드에 쓰는 한 줄. 항상 L1 톤으로.",
  "prereq": ["temperature"],
  "next": ["gibbs-free-energy"],
  "terms": {
    "미시상태": { "brief": "툴팁에 뜰 한 줄 설명", "slug": "선택: 독립 문서가 있으면" }
  },
  "blocks": [
    { "type": "oneline", "byLevel": { "1": "...", "3": "..." } },
    { "type": "math", "minLevel": 3, "byLevel": { "3": "..." } }
  ]
}
```

**`byLevel`은 모든 레벨을 채우지 않아도 됩니다.** 비어 있는 레벨은 바로 아래 레벨 원고를
그대로 씁니다. 위 예시의 `oneline`은 L1·L2에 첫 글, L3·L4·L5에 둘째 글이 뜹니다.
이 fallback 덕분에 집필량이 레벨 수만큼 배가되지 않습니다.

### 본문 인라인 문법

| 문법 | 결과 |
|---|---|
| `$...$` | 인라인 수식 (KaTeX) |
| `$$...$$` | 블록 수식 — 한 문단을 통째로 차지하게 두면 가장 깔끔합니다 |
| `[[용어]]` | 점선 밑줄 + 툴팁. `terms`에 등록된 것만 |
| `**강조**` | 굵게 |

문단은 빈 줄(`\n\n`)로 나눕니다.

### 검사

`npm run validate`가 잡아 주는 것:

- 파일명과 `slug` 불일치, 빠진 `oneline` 블록
- 1~5 밖의 레벨 키, `minLevel > maxLevel`
- 등장 구간 밖에 있어 영원히 안 보이는 원고
- `terms`에 없는 `[[용어]]`, 본문에서 안 쓰이는 `terms` 항목
- 짝이 안 맞는 `$`
- 아직 없는 문서를 가리키는 `prereq` / `next` / `terms[].slug`

없는 문서를 가리키는 링크는 **경고**일 뿐 오류가 아닙니다. 집필 중에는 링크가 먼저
앞서 나가기 마련이고, 화면에서는 조용히 빠집니다.

## 도표와 출처

문서마다 필요한 곳에 `![캡션](/figures/파일명.svg)`로 도표를 넣었습니다. 전부 `public/figures/`에
직접 그린 SVG입니다. 열역학은 사진으로 설명되는 분야가 거의 없고(엔트로피는 찍을 수 없으니)
웹 이미지는 저작권 문제가 있어, 라이선스 걱정 없이 다크모드에도 반응하는 SVG를 택했습니다.
`Concept.sources`에 참고 서적·논문을 넣으면 본문 하단에 작게 뜨고, `minLevel`을 주면 상위
레벨에서만(예: 원 논문은 L4·L5에서만) 노출됩니다.

## 남은 일

- **콘텐츠.** 지금 열역학 13개 — 온도·열·일·내부에너지·엔탈피·엔트로피·제2법칙·카르노 기관·
  이상기체·헬름홀츠 자유에너지·깁스 자유에너지·화학퍼텐셜·상전이. 서로 `prereq`/`next`로
  엮여 하나의 지도를 이룹니다. 다음 분야(역학·전자기학 등)를 새로 시작할 때도 같은 규모
  (10개 이상)로 채워야 "빈 사이트"처럼 보이지 않습니다.
- **"여기서 막혔어요" 로그.** 지금은 `localStorage`에만 쌓입니다. 서버로 보내면
  *어느 개념 어느 레벨의 설명이 부실한지*가 그대로 집필 우선순위가 됩니다.
- **L4·L5 검수.** 초안을 LLM으로 뽑더라도 이 두 레벨은 직접 확인해야 합니다.
  사이트 신뢰도가 여기서 갈립니다.
- **공유 카드.** 현재는 URL 복사만 됩니다. 레벨이 박힌 이미지 카드를 만들면
  인스타·트위터 유입 경로가 생깁니다.
